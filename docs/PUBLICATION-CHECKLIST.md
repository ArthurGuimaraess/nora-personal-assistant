# Before publishing or sharing NORA

- [ ] Keep .env, API keys, certificates and tokens private.
- [ ] Do not upload the real data directory, SQLite database, backups, user exports, photos or logs containing personal information.
- [ ] Review every screenshot for names, email addresses, medication details or other private information.
- [ ] Use only fictitious accounts and test content in demos.
- [ ] Keep the public demo local-only until authentication, authorization, rate limiting, HTTPS, CSRF protections and deployment hardening are implemented and reviewed.
- [ ] Confirm rights and licensing for every sound, image, icon and other media asset before distributing it.
- [ ] Configure quotas, billing alerts and usage controls with API providers independently of NORA's internal counters.
- [ ] Test Android on physical devices and with accessibility services before claiming full compatibility.
- [ ] Do not present mental-health, sleep, medication, SOS or notification features as clinically validated or guaranteed.
- [ ] Review all supportive language for shame, pressure, stigma, compulsive reassurance or unintended reinforcement of harmful loops.
- [ ] Involve qualified mental-health, neurodiversity and accessibility professionals before adding condition-specific or clinical claims.
- [ ] Clearly distinguish features available today from research, roadmap ideas and future directions.
